# Experiment and data guide

The experiment numbers follow the current second-revision manuscript, not older script headings. Some copied comments and result keys retain earlier terminology; their interpretation below follows the current paper.

## Current data

| File | Contents and interpretation |
| --- | --- |
| `curvature_aware_deeponet/results/poc_results.json` | Experiment 1: 20 per-run records under `runs`, aggregated mean/std and improvement under `summary`. Controlled endpoint calibration. |
| `curvature_aware_deeponet/results/remaining_v2.json` | Experiment 2 (`experiment2`): mean/std continuity and Kirchhoff metrics; Experiment 3 (`experiment3`): bias-amplitude sweep; Experiment 4 (`experiment4`): actual graph counts, FVM time and coupling time. `experiment5` is an additional topology run and is not the source of the paper's Experiment 5 table. |
| `results/largescale_scalability.json` | Experiment 4b. Keys are requested vertex targets; `n_vertices` and `n_edges` are actual generated sizes. | `results/epsilon_ablation.json` | Experiment 4c. Keys are threshold strings. Stores `frac_curved`, flat/calibrated continuity errors and improvement percentage. The graph has 25 vertices and uses prescribed sinusoidal curvature; this is not a noisy-curvature robustness test. |
| `curvature_aware_deeponet/results/exp5_exp6.json` | **Only `experiment5` supplies the paper's Experiment 5 topology table.** Its `experiment6` contains an older noise/improvement-factor surrogate; it is not the current inverse table and is not the current baseline comparison. The extra Example5 row is also not a distinct reported topology. |
| `curvature_aware_deeponet/results/comparison.json` | `partA`: Experiment 6's algebraic baseline surrogates, not separately trained PI-DeepONet/XPINN models. `partB`: Experiment 7's independent sphere transport comparison; angle error is radians, execution time is microseconds. |
| `results/transport_mesh_validation.json` | `surface_validation`: Experiment 7b tangency, norm and reverse-edge diagnostics on sphere/torus/paraboloid/wrinkle; `scalability` and `fit`: Experiment 7c transport-kernel timing and linear fit. | `results/inverse_poc.json` | Experiment 8: grid search plus local refinement for drift velocity, 15 trials per prescribed curvature level. Contains velocity MAE and improvement percentage. Uses a known measurement-bias model rather than transport of a scalar flux. |

Historical names such as `curv_*`, `Ours (PT)`, `+CurvSensor`, `+PT+Tensor` and `Full (Ours)` are preserved for data integrity. In the controlled experiments they describe calibration branches/surrogates, not evidence of trained neural components. Experiment 2's relevant strengths are 0%, 55%, 70%, 85% and 100%; the `+CurvSensor` result duplicates the 0% branch.

## Inputs, seeds and resolutions

Inputs are generated by the Python scripts. Keep the graph/FVM source and both relative project paths. Gaussian-process inputs for the restored FVM runs use the local reference `src/GPs.py`, whose `random` object is a NumPy compatibility implementation. It is not bit-for-bit equivalent to JAX's PRNG. The separate `curvature_aware_deeponet/src/GPs.py` remains a JAX prototype.

Read each script for the authoritative seeds and parameters. The protocols differ: the inverse script uses `nx=80`, `nt=400`; the restored graph FVM scripts typically use `nx=200`, `nt=1000`; transport validation uses 24×24 meshes and a separate torus-size sweep. The forward PoC assigns seeded random vertex curvature, while other controlled sweeps prescribe sinusoidal curvature. Thus a blanket parameter description in the manuscript should not be assumed to override the actual script settings.

The results are mainly aggregate JSON outputs. `poc_results.json` also records each run, but the workspace does not supply a complete per-trial dataset for every other experiment or a full neural training dataset. No missing raw data or historical code has been reconstructed.

## Earlier material

`archive/legacy/` retains earlier scripts, JSON, a small pickle result and console logs at their original relative paths within the archive. They have different protocols or recorded values and are not sources for the current paper's tables. Consult the archive README before attempting to run its code.

## Rerunning

Use the commands in the root README from the repository root. Several scripts execute experiments immediately when imported; do not import them merely to inspect their functions. Run experiments in a separate working copy because they overwrite recorded result files. The immutable source-file hashes in `manifest.csv` describe the packaged snapshot, not future rerun outputs.
